# 投稿スケジュール設計スキル

## Knowledge参照（必須）:
- `ai-agent-organization/shared/knowledge/教育大全.md` ← 6つの教育カテゴリーと順序設計

- `ai-agent-organization/organization/operations/x-post-creator-X_POST_CREATOR/knowledge/knowhow/strategy-brief.md` ← X投稿の戦略ブリーフ

# ===== Phase A: ヒアリング =====

スキル発動時、以下の3点を簡潔に確認する。
**一度に全部聞く。分けて聞かない。**

```
投稿スケジュールを設計します。以下を教えてください：

① 期間と1日の投稿数（例：5日間 × 1日5投稿）
② 何の投稿か（販売するもの・テーマ・目的）
③ ターゲット（どんな人に届けたいか。ざっくりでOK）
```

回答を受けたら、確認なしにPhase Bへ進む。

---

# ===== Phase B: ターゲット・悩み・切り口の設計 =====

## Step B-1: ターゲット定義の精緻化

ヒアリング回答と `master-strategy.md` のターゲット定義をもとに、以下を設計する。

```
【ターゲット像】
・現在の状態：[何をしている/何を使っている/どんな状況]
・抱えている問題：[うっすら感じている・でも言語化できていない痛み]
・理想の状態：[本当は手に入れたい状態]
・購買動機：[なぜこれを買うのか]
```

## Step B-2: ターゲットの悩みを10個列挙

ターゲットが抱えている具体的な悩みを10個挙げる。
「あ、これ自分のことだ」と思わせる具体性で描写すること。

### 出力フォーマット：
```
1. [悩みの具体的描写 - 1〜2文。抽象的ではなく、シチュエーションが見えるレベルで]
2. ...（10個）
```

## Step B-3: 有益な切り口を列挙

テーマに対して、投稿として使えそうな切り口・角度・アプローチを15個列挙する。
以下の種類を混在させること：

- 問題提起型（「〜が実はこういう問題だった」）
- 反常識型（「〜と思われがちだが実は逆」）
- Before/After型（「〜前と〜後でこう変わった」）
- 概念教育型（「〜とは何か、一言で言うと」）
- 数字型（「〜に費やしてる時間を計算した」）
- 理想描写型（「〜ができるようになると1日がこう変わる」）
- 実演・証拠型（「実際にやってみた結果」）
- 投資合理性型（「〜に投資すると〜が変わる計算になる」）
- 比較型（「〜と〜を比較すると」）

### 出力フォーマット：
```
【切り口リスト】
1. [切り口] ← [種類]
2. ...（15個）
```

# ===== Phase C: 教育フレームワーク×フックで強化 =====

## Step C-1: 教育アークの設計

`教育大全.md` を参照し、全投稿数を6つの教育カテゴリーにマッピングする。

**教育の順序原則**：
```
問題点の教育 → 手段の教育（概念） → 理想の未来の教育 → 信頼の教育 → 投資の教育 → 販売
```

期間・投稿数に応じて各教育の割り当て本数を決定する。

### 出力フォーマット：
```
【教育アーク】
Day1（〇本）：問題点の教育 → 目的：「自分の話だ」と思わせる
Day2（〇本）：問題点の深掘り＋手段の教育 → 目的：根本原因を腑に落とす
Day3（〇本）：理想の未来の教育 → 目的：「欲しい」感情を作る
Day4（〇本）：信頼の教育＋投資の教育 → 目的：「この人から買う理由」を作る
Day5（〇本）：全教育の統合＋購買誘導 → 目的：「明日絶対買う」状態にする
※日数が異なる場合は比率を保ちながら調整
```

## Step C-2: 各投稿の1行目フック設計

Phase Bの切り口リストと `hook-design-principles.md` のフック7パターンを組み合わせ、
**全投稿数分のフック（1行目）を設計する**。

フック設計の絶対ルール：
- ターゲットが1行目で「これは自分への話だ」と判断できること
- 問題点または理想の未来が具体的に含まれていること
- 抽象語（「効率化」「楽になる」「すごい」）だけで終わらないこと
- 断言形式にすること（「〜かもしれない」禁止）
- 「タイトルっぽい」だけで終わらないこと

### 出力フォーマット：
```
投稿①：[1行目フック]（使用パターン：〇〇型）
投稿②：[1行目フック]（使用パターン：〇〇型）
...（全本数分）
```

# ===== Phase D: スケジューリング =====

## Step D-1: 完全スケジュール表の作成

Phase C までの設計を統合し、全投稿のスケジュール表を作成する。

### 出力フォーマット：
```
## [タイトル] 投稿スケジュール（全〇本）

---

### Day〇（日付）：〇投稿 ── [その日のテーマ・目的]
教育テーマ：[担当する教育カテゴリー]

---

投稿① 【長文 / 短文 / 問いかけ】
1行目フック：
> [フック文]

教育：[カテゴリー]
フックパターン：[種類]
本文の方向：
- [ポイント1]
- [ポイント2]
- [着地点]

---

投稿② 【長文 / 短文】
...（以下繰り返し）
```

## Step D-2: フォーマット配分の確認

スケジュール完成後、以下の配分を確認・明示する：
- 長文投稿：〇本
- 短文投稿：〇本
- 問いかけ投稿：〇本
- 教育別配分（カテゴリーごとの本数）

## Step D-3: フックチェック

全投稿のフックに対して以下のチェックリストを適用し、NGがあれば修正する：

- [ ] ターゲット明示あり
- [ ] 問題点または理想の未来が具体的
- [ ] 抽象語だけで終わっていない
- [ ] 断言形式
- [ ] 「タイトルっぽいだけ」になっていない

## 絶対条件:
- Phase A のヒアリングは一度に全項目を聞く（分割しない）
- フックは「タイトルっぽいだけ」に絶対にならない。必ず問題点か理想の未来が入ること
- 教育の順序（問題→手段→理想→信頼→投資→販売）は守ること
- 教育大全・フック設計原則を必ず参照してから設計すること
- 指示の復唱・余計な補足は入れない
