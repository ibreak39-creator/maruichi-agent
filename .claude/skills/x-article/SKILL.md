## アルゴリズムの理解（前提知識）

Xのアルゴリズムにおいて、現在最も強力なシグナルは **「ブックマーク（保存）」と「滞在時間」**。
インプレッションを最大化するには、これら2つを最優先で設計する。

- いいね・RTより「保存」が評価される時代
- 長く読まれる記事 = 滞在時間が伸びる = 拡散される
- 図解・リストは「保存させる仕掛け」の筆頭

## バズを生む「黄金の方程式」（6要素）

**この6要素をすべて満たす記事を目指すこと。1つでも欠けると平均以下になる。**

1. **圧倒的なリアル感と熱量**
   - 自分の発信や体験に対する熱量とリアルさがすべての土台
   - AIが生成した「きれいな文章」ではなく、一次情報が滲み出る文章を書く

2. **独自の視点と切り口**
   - 情報を横流しするのではなく、自分だけの味・特徴を持たせる
   - 「誰でも言えること」は書かない。「自分だから言えること」だけを書く

3. **仕組みの解説（理由の先まで語る）**
   - 単なる「理由」で終わらせず、その先の「なぜそうなるのかという仕組み」まで語る
   - 「〇〇だから→××になる→その根本は△△にある」という因果の連鎖で書く

4. **強い一次情報**
   - 自分の実体験・コンプレックス・失敗談を具体的に組み込む
   - 書籍の知識、有名人の言葉、データなどで説得力を底上げする（一次情報のトッピング）

5. **保存させる仕掛け**
   - 図解・リスト・箇条書きなど、読者が思わずブックマークしたくなる要素を用意する
   - 「これを保存しておけば後で使える」と思わせる実用性を入れる

6. **世界観と表現力**
   - 自分の文体・スタイルを統一し、読者との関係性を構築する
   - writing-style-profile.mdで定義されたキャラクターを徹底して守る

## ポジションと界隈の設計（記事を書く前に決める）

### 5つのキャラクター設定（どれで戦うかを決める）

| キャラクター | 内容 | 必須条件 |
|------------|------|---------|
| **まとめ系** | 情報を収集・整理して届ける | リサーチ力 |
| **言語化系** | 曖昧な概念を明確に言葉にする | 思考力 |
| **リサーチ系** | 深い調査・分析を届ける | 専門知識 |
| **ストーリー系** | 体験・感情の流れで伝える | 一次情報 |
| **先生系** | 教える立場で体系的に届ける | **圧倒的な実績が必須** |

### 冒頭4〜6行での「自己定義」

**記事の最初の4〜6行で以下をすべて定義すること:**
- 自分が何者で
- どの立場から
- 何のテーマを
- なぜ読者は読むべきか

これを定義しないと、読者は「誰が書いたのか」がわからず離脱する。

## 記事構成の設計原則

### 全体の流れ（必ずこの順序で設計する）

```
[記事タイトル]（クリックしたくなるタイトル）
      ↓
[冒頭4〜6行の自己定義＋フック]
      ↓
[問題提起]（読者の「痛み」の言語化）
      ↓
[中心テーゼ：なぜ○○なのか]（結論の提示）
      ↓
[因数分解：理由① / 理由② / 理由③...]（各要因を仕組みレベルまで掘り下げ）
      ↓
[証拠・根拠]（数字・実体験・Before/After）
      ↓
[締め]（冒頭フックと呼応するオチで完結させる）
```

### 記事タイトルの設計

**タイトルの長さルール（最重要）**:
- **20〜30文字以内を目安**にする。長すぎるタイトルは読まれない
- 数字＋ベネフィット＋ターゲットを凝縮する
- NG例: 「偏差値33の僕が、2年でライティングで月160万稼げるようになった話」（長すぎ・自分語り）
- OK例: 「AI時代に必要なライティング力を上げる、たった3つの方法」（短く・具体的・ベネフィット明確）

**クリックしたくなるタイトルの条件**:
- 数字を入れる（「〇つの」「〇分で」「〇%の」）
- ターゲットを明示する（「副業をしてる人へ」「AIを使ってるのに〜な人」）
- 反常識・逆説を入れる（「〜はむしろ逆効果だった」）
- 「Before/After」の数字対比（「1日6時間 → 2時間になった方法」）
- 問いかけ型より断言型が強い

**タイトルのNG例**:
- 「〇〇の話をします」（情報量ゼロ）
- 「〇〇について解説」（タイトルっぽいだけ）
- 「〇〇のコツ」（具体性なし）
- 長すぎる自己紹介型タイトル（「〇〇な僕が〜できるようになった話」）

### 冒頭フックの設計（最重要）

**hook-design-principles.mdの7パターンから最適なものを選ぶ**

冒頭3〜5文すべてを通じて「刺し」の鋭さを維持すること。

**Xのリアルな声を使った共感フック（推奨パターン・必須ルール）**:

**【冒頭3行の絶対ルール】**
最初の3行は、必ず「」（カギカッコ）で読者が実際に思っていることを書く。
以下の3種類を組み合わせて2〜3個並べる：
1. テーマへの疑問・懐疑心（「〜って結局何がすごいの？」）
2. 行動の壁・面倒さ（「〜って毎回やるの面倒だし…」）
3. **SNSあるある（必ず1つ入れる）**: Xやネット上でよく見る誇大な主張に対して「自分には関係ない」「どうせ無理」と感じているモヤモヤ

その後「って思ってる人、実は多いんじゃないかと思います。」で共感。
さらに「僕も、最初はそうでした。」の自己開示を入れて信頼を作る。
その後で衝撃の実態・逆説に転換する。

- 効果: 共感で引き込む → 自己開示で信頼 → 逆説で掴む → 一次情報で信頼させる
- 例:
  ```
  「Claude Codeすごいって聞くけど、
  結局何がすごいの？」

  「プロンプト毎回書くの面倒だし、
  普通のChatGPTと何が違うの…？」

  「Xで『エージェントで自動化できる』って
  投稿よく見るけど、自分には関係ない話だよな」

  って思ってる人、
  実は多いんじゃないかと思います。

  僕も、最初はそうでした。

  でも「todaystart」と打つだけで、
  メルマガとX投稿が勝手に生成されてる。
  ```

- 旧例（基本形として保持）:
  ```
  「文章力は才能だ」
  「センスがない人は書けない」
  「ライティングなんて食えない」

  僕も最初はそう思ってました。
  でも、その3つは全部、仕組みを知れば覆せることだったんです。
  ```

**禁止パターン**:
- 「〇〇する人、めちゃ多いんですよね。」→ 読者が傍観者になる
- 1〜2文目がよくても3文目で「普通」になるパターン

**意識すること**:
- 読者が「自分のことだ」とドキッとする表現になっているか書いた後に自問する
- 1行目は「もっと見る」前に意味が伝わる独立した文として成立させる
- フックで引いた「約束」は必ず本文で回収する

### アナロジー（たとえ話）の使い方

複数の概念（3つ以上）をアナロジーで説明する場合、**必ずアナロジーの前に各要素の短い説明を入れる**。
順序：① 概念の簡潔な説明（各1〜3行）→ ② 「料理で例えると」などアナロジーで直感的に定着させる。

- NG: いきなりアナロジーだけで説明（読者が何の話か掴めない）
- OK:
  ```
  エージェントは「AIの司令塔・脳みそ」。
  何をするか判断して、タスクをまとめる役割。

  スキルは「AIへの具体的な指示・能力」。
  プロンプトを型にしたもの、と思ってもらえれば。

  MCPは「外部ツールへの接続口」。
  GoogleカレンダーやドライブとつなぐAIの道具箱。

  料理で例えると、
  エージェントは「今日夜ご飯何にするか決める人」。
  スキルは「包丁やフライパンを使う行為」。
  MCPは「冷蔵庫みたいなもの」です。
  ```

## 反応を高める執筆テクニック

### パワーフレーズの詰め込み

短い文字数に以下の4要素を凝縮する:
- **ターゲット**: 誰に向けているか
- **悩み**: その人の具体的な問題
- **コンプレックス**: 悩みの根源にある感情
- **ステータス**: 本能的に求めている理想の状態

### 知っていること×知らないこと

「言語化がうまい人の正体は（知っている）、流れで捉える人（知らない）」のように、
読者が「知っているもの」と「知らないもの」を掛け合わせて興味を惹く。

### 仕組みの因数分解

抽象的な概念（例：努力・人生設計）は「〇〇×〇〇」の掛け算や「5つのポイント」などに因数分解する。
網羅性と有益性が上がり、「保存してまとめて読みたい」記事になる。

### 一次情報のトッピング

自分語りだけでなく、以下を追加して説得力を底上げする:
- 書籍の知識・引用
- 有名人の言葉
- AIで調べたデータ・統計
- 客観的な事実・研究結果

## デザインと離脱防止策

### パンチラインの活用

見出しや文章の要所に、目を引く強烈なコピーを配置する。
例:「夜更かしは人生のリボ払い」

抽象的な説明をシンプルな一言で刺すことで、記憶に残り引用RTされやすくなる。

### 箇条書きの挿入

文章の連続を避け、定期的に箇条書きを使って視覚的なリズムを作る。
3〜4項目が上限。箇条書きが「保存したくなる」密度を作る。

### 図解の早期投入

抽象度の高い話をする際は、概念を説明する図解や画像を早めに挿入する。
図解があると滞在時間が伸び、アルゴリズムに優遇される。

## インプレッション最大化の戦術

### ターゲット絞り込みによる刺さり設計

ターゲットを絞るほど、該当者には深く刺さりインプレッションが上がる。

- 「副業している人」より「副業で月5万を目指してるのに3ヶ月結果が出ない人」
- 「AIを使っている人」より「ChatGPTを毎日使ってるのに手間が減らないと感じている人」

### フック強度を上げる3つの方法

1. **ターゲットを1行目で明示する**（「副業をしている人」「AIを毎日使っているのに成果が出ない人」）
2. **数字で痛みを可視化する**（「月〇時間が無駄になってる計算」「3ヶ月分の機会損失」）
3. **反常識・逆説を断言する**（「〇〇はむしろ逆効果だった」「〜より〜の方が10倍早い」）

### RT・引用RTを誘発するコンテンツ設計

**シェアされる記事の共通要素**:
- 「まとめ」が秀逸（スクショで保存したくなる密度）
- 「反常識」な主張（「え、そういうこと？」という気づきが拡散を生む）
- 「自分も同じだった」という共感（引用RTに「これ自分のことすぎる」がつく）
- 誰かに教えたくなる情報（「これ知らない人に送りたい」）

## 投稿後の運用とブースト戦略

記事は「出して終わり」ではなく、そこからの運用がインプレッションを左右する。
**出力フォーマットの「運用プラン」欄に以下を記載すること。**

1. **セルフ引用（投稿約1時間後）**: 自分で自分の記事を引用ポストして露出を増やす
2. **翌日の図解引用**: 翌日、記事内に使った「図解」だけを抜き出して引用ポストし、記事本体へアクセスを流す
3. **仲間との相互引用**: 界隈の良い記事を引用して宣伝し合い、インプレッションを高めるループを作る

## 文章設計ルール

### 基本スタイル

- 一人称は「僕」、二人称は「あなた」
- 基本トーン: 親しみやすく励まし中心。断定的だが攻撃的でない
- 逆説構文を多用（「〜ではない。〜だ。」）
- 抽象と具体を往復する（抽象 → 具体 → 再抽象）
- 結論ファースト（最初に結論、後に理由）
- ハッシュタグは使用しない
- 絵文字は最小限（0〜2個程度）

### 改行・リズムのルール

- 句読点で改行（スマホ縦読みに最適化）
- 2文以上続いたら改段落を挟む
- **1文内途中改行で「ためて→落とす」リズムを設計する**
- **接続詞1語を独立段落として使う**（1〜2箇所に限定）

### 文体のモジュレーション

2〜3段落に1回のペースで以下のいずれかのブレイクポイントを仕掛ける:

- **擬音・副詞**: 「ゴリゴリ」「ガンガン」「ズコー」など場面を想起させる表現
- **具体例・たとえ話**: 「例えば、」で抽象から具体に降りる。1〜2文でシンプルに
- **読者の心の声・セリフ**: 「「これなら自分でやった方が早い」って思いますよね。」で引き込み、そこからひっくり返す

### ━━━の使い方（最重要・1〜2箇所まで）

━━━の中身は**完結した文章ではなく、前後の文と繋がって1文になるフレーズ**

```
前の文（主語・状況説明） →

━━━━━━━━━━━━━
フレーズ（10〜25文字）
━━━━━━━━━━━━━

→ 受けの文（締め）
```

**良い例**:
```
エージェントのメリットって時短ではなくて、

━━━━━━━━━━━━━
使ってる間の時間の密度が上がること
━━━━━━━━━━━━━

なんですよね
```

## AI臭さ排除ルール（必須）:

- 安全クッション（「一般的に」「多くの場合」「一概には言えませんが」）は削除。言い切る
- 抽象語（「重要」「効果的」「本質」）だけで押し切らない。具体的に何がどうなるか書く
- 同義語の言い換え連打はせず、1回で言い切る
- 短い文と長い文を混ぜ、文のリズムを均一にしない
- 「--」は絶対に使わない（AIっぽくなるため）
- 締め定型句（「参考になれば幸いです」「いかがでしたでしょうか」等）は使わない
- 前置き宣言（「本記事では〜について解説します」等）は入れない
- **直接宣言を避ける（重要）**: 「なぜかを因数分解してみました。」のような直接的・AI臭い宣言表現を使わない。「少し整理してみます。」など間接的・自然な誘導表現に置き換える
- **語尾の連続防止（重要）**: `sentence-ending-patterns.md` を参照し、同じ語尾を2回連続させない。記事作成後に全文の語尾パターンをチェックし、連続があれば修正すること

## 実行内容（4フェーズ分割確認フロー）:

**各フェーズ完了後、必ずユーザーに確認を取ってから次のフェーズに進むこと。**

---

### Phase 1: ヒアリング

ユーザーのテーマ・伝えたいこと・ターゲット読者・使いたい一次情報を受け取る。
情報が不足している場合は以下を質問する:
- 記事で伝えたいことは何か
- ターゲット読者は誰か（どんな悩みを持つ人か）
- 使いたい一次情報（実体験・失敗談・データ）はあるか

→ 確認ポイント：「このテーマ・方向性で進めますか？」

---

### Phase 2: Webリサーチ

WebSearchツールでテーマに関連する以下を収集する:
- 最新の情報・データ・統計
- 反常識な視点・逆説的な事実
- 読者が知らなそうな切り口

リサーチ結果の要点を箇条書き（5〜8点）で共有する。

→ 確認ポイント：「このリサーチ結果を使って構成を作ります。追加で調べてほしいことはありますか？」

---

### Phase 3: タイトル・構成作成

**Step 1: ポジション設定**
5つのキャラクター（まとめ系/言語化系/リサーチ系/ストーリー系/先生系）のどれで書くかを決める。

**Step 2: 教育設計**
この記事が担う教育カテゴリを決める（問題点/理想の未来/信頼/手段/投資のどれか）。

**Step 3: 黄金の方程式チェック**
記事を書く前に6要素をどう盛り込むか設計する。

**Step 4: タイトル3案を提示**
クリックしたくなるタイトル設計の条件に従って3案を提示する。

**Step 5: 因数分解構成を提示**
「なぜ○○なのか」を中心テーゼとした構成を設計する。
理由を2〜4要因に分解し、各要因を見出しにした構成案を提示する。

→ 確認ポイント：「このタイトル・構成で進めますか？修正点はありますか？」

---

### Phase 4: 見出しごとに執筆

OKをもらったら、**見出し1つずつ書いて確認を取りながら進める**。

各見出しを執筆したら：「次の見出しに進みますか？」と確認する。

全見出し完了後にセルフチェックを実施する:
- 語尾の連続がないか確認し、あれば修正する
- AI臭さ排除ルールをすべてクリアしているか確認する
- 黄金の方程式の6要素が全部設計されているか確認する
- 「ブックマークしたくなる」要素があるか確認する
