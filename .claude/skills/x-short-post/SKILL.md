## 投稿構成

### 基本構造（この順序を厳守）

```
[フック]
[本文]
[CTA]
```

### 文字数
- **140文字以内**に収める
- フック→本文→CTAを1投稿内で完結させる
- 文字数カウントは投稿本文のみ（改行含む）

---

## フック設計（最重要）

ターゲットに「これは絶対見なければ！」と思わせる強烈な1行を冒頭に置く。
writing-style-profile.md のフックパターンから文脈に合うものを選択する。

### パターン1: 読者の思い込みを否定する
```
「副業勢だから本業勢に負ける…」って思ってる人、完全に逆です。
```

### パターン2: 対象者を絞り込んで呼びかける
```
AIが思った通りに動いてくれない人へ。
```

### パターン3: 意外性のある断言
```
あんまり騒がれてないんですけど、〇〇はめちゃ化けると思います。笑
```

### パターン4: 問いかけ
```
この差、分かりますか？
```

### パターン5: 問題提起型（新規層に最も刺さる）
ターゲットが抱える問題を「多い」「極めて多い」という言葉で先に言語化する。読者が「自分のことだ」と感じる自己投影を引き起こす。
```
「AIを使えば稼げると思っている人があまりにも多いですが、正確には違います。」
「〇〇できない人はつい〜してしまう。」
「〇〇が極めて多い。」
```

### パターン6: 逆張り教育型（強い主張を断言）
「持論」「偏見」「ぶっちゃけ」と断りを入れてから断言する。炎上リスクを下げながら強い主張を展開できる。
```
「くそぶっちゃけると、AIで稼げない人の99%は才能の問題じゃないです。」
「偏見だけど、〜」
「持論ですが、〜」
```

### パターン7: 体験引用型（競合分析上 平均4,527imp）
他者の声・体験を借りる。信頼性を上げながら自慢を回避できる構造。
```
「〇〇な方から連絡が来た。」
「先日〇〇している読者さんが言っていた。」
「コンサルした方が言っていた。〜」
```

### フックのNG例（使わない）
- 「今回は〜について解説します」
- 「〜のコツを紹介します」
- 「〇〇する人、めちゃ多いんですよね。」→ 読者が傍観者になる

---

### フック設計の補足: ターゲットの内なる言葉を先回り言語化する

ターゲットが心の中で感じているが言語化できていない不安・悩みを先回りして書く。
「やってはいるけど結果が見えない」「何が正解かわからない」「自分だけ取り残されている気がする」——これらは言葉にならないまま溜まっている感情だ。
それをフックで先に言葉にすることで、「これは自分のことだ」という強い自己投影を引き起こす。

### 新規層リーチの原則

- フックの1行目は「既存フォロワー」ではなく、**「初めて見る人」**に向けて書く
- 共通の悩み・あるあるから入り、まるいちの視点で転換させる構造にする
- 「AI副業を始めたのに結果が出ない」「頑張っているのに報われない」という普遍的な感情を入口にする

---

### パワーワードリスト（競合分析で高インプレッション確認済み）

まるいちの文脈に合うパワーワードを優先使用する。

| カテゴリ | ワード例 |
|---------|---------|
| 信頼性の演出 | 「ガチで」「ぶっちゃけ」「リアルに言うと」 |
| 否定から始める | 「〜ではない。〜だ。」（逆説構文） |
| 構造化ワード | 「しくみ」「ロードマップ」「型」「再現できる」 |
| 心理ワード | 「腑に落ちる」「気づかせる」「前提が壊れる」 |
| 敷居を下げるワード | 「ノースキルでいける」「普通の人でも」「初心者でも」 |

## 本文設計

- 箇条書き（・）を使うか、1〜2文でゴリゴリの有益な内容を書く
- **視認性を最優先**（短い行、改行を適切に使用）
- 情報密度を高める。冗長NG
- 1段落は1〜2文が上限。長くなったら分割する
- 同じことを言い方を変えて繰り返さない。言い切ったら次へ進む

### 否定語の後には必ず共感フレーズを入れる（必須ルール）

「〜じゃないです」「〜はダメ」「〜ではない」などの否定的な言葉は強力だが、単体で使うと読者が離れる。
**必ず直後に「あるある」「共感」を引き出すフレーズをセットで置く**こと。

```
[構造]
否定 → 共感（あるある・読者が「そうそう」と感じられる言葉）→ 本質へ

[例]
「完璧な指示を出せてる人って、実はいないです。」  ← 否定
「他人の気持ちが100%汲み取れないじゃないですか。」  ← 共感（あるある）
「それと同じで、AIの考えてることも分からないんです。」  ← 本質へ
```

共感フレーズのパターン：
- 「〜じゃないですか。」（読者も同じ体験をしているはずという問いかけ）
- 「〜って、みんなそうですよね。」
- 「〜って、なかなかできないですよね。」
- 「〜って正直ムリじゃないですか。」

## CTA設計

読者が「何らかの行動を起こすきっかけ」「気づきを得る」ことが目的。
**CTAは1つに絞る**。

| CTAタイプ | 使用場面 | 例 |
|----------|---------|-----|
| 明示的（ブクマ推奨） | 情報を保存したくなるノウハウ系 | 「保存推奨です。」 |
| 明示的（リプください） | 議論・共有を促したいとき | 「あなたはどうですか？」 |
| 間接的（共感問いかけ） | 読者に気づかせたいとき | 「こんな経験ありませんか。」 |
| 行動促進 | 今すぐ動いてほしいとき | 「ぜひ試してみてください。」 |

## AI臭さ排除ルール（必須）

- 「一般的に」「多くの場合」→ 言い切る（「9割は」「ほとんどの人は」）
- 抽象語だけの主張NG → 具体的に何がどうなるか書く
- **体言止め禁止**: 文・投稿を体言止めで締めない。必ず「です・ます調」または自然な崩し語尾で終わらせること
- **語尾の連続禁止**: sentence-ending-patterns.md を参照し、同じ語尾を2回連続させない
- 「なんですよね」は全体で2回以内（短文なのでより厳格に管理する）
- 「--」は絶対使わない
- 締め定型句（「参考になれば幸いです」「いかがでしたでしょうか」等）は使わない
- 「〜について解説します」「〜を紹介します」などの前置きを入れない

## 3案作成ルール

**必ず3案を出力する**。それぞれ異なるフックパターンを使い、切り口を変える。

- 案1: パターン1・2・5のいずれか（読者への呼びかけ・問題提起系）
- 案2: パターン3・4・6のいずれか（断言・逆張り・意外性系）
- 案3: パターン7（体験引用型）、または1〜6のうち案1・案2と最も切り口が異なるもの

同じ表現・同じ構造の繰り返しは禁止。3案それぞれに個性を持たせる。

## 出力形式

前置き・解説不要。投稿本文のみ出力する。

```
【案1】
[投稿本文]

文字数: ○文字

---

【案2】
[投稿本文]

文字数: ○文字

---

【案3】
[投稿本文]

文字数: ○文字
```

投稿本文作成後、必ず全案の語尾パターンを確認し、同じ語尾が2回連続していないかチェックすること。連続があれば別カテゴリ（A〜F）の語尾に差し替えて出力する。
