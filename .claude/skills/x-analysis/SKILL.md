# X競合アカウント分析スキル

## 目的
同ジャンルの競合Xアカウントと自分を比較分析し、具体的な改善アクションを導き出す

## 使い方
/x-analysis @自分のXアカウントのID @競合1 @競合2 @競合3

- 最初が自分のアカウント
- 2つ目以降が競合（最大10件）
- IDなしで実行した場合は聞く

## 進行フロー

### 1. XアカウントIDの確認
- 引数の1つ目を自分のアカウントとして扱う
- 2つ目以降を競合リストとして扱う
- 引数がない場合：「自分のXアカウントのIDと、比較したい競合のIDを教えてください」と聞く
- 比較適正チェック: フォロワー数や実績が自分と差がありすぎる場合は警告する。格上すぎる相手との比較は意味が薄い。ただし、フォロワーが少なくても実績（売上・ローンチ規模等）が上の場合は比較対象として有効

### 2. ユーザー背景のヒアリング

データ収集に入る前に、ユーザーの背景を確認する。数字やプロフィール文だけでは「なぜこのビジネスをやっているか」が抜け落ち、改善提案の方向性がズレるため。

以下を聞く（一度にまとめて聞く）：
1. 参入経緯 — なぜこのビジネスを始めたか
2. 現在の本業 — 他に何をやっているか（兼業・副業の場合）
3. 前回からの変化 — 商品・実績・方針で変わったことがあるか（2回目以降）

「最大の武器」「差別化ポイント」は聞かない。答えられないユーザーが多い。参入経緯と本業の事実から、差別化ポイントはこちらが分析して導き出す。

### 3. データ収集（A: Playwright自動収集 → B: Web検索 → C: 手動入力）

自分のアカウント・競合アカウントの両方について、以下の順で試みる。

#### 方法A: Playwright自動収集（Playwrightプラグインがある場合）
1. Playwrightでブラウザを起動する
2. https://x.com/{handle} にアクセスする
3. プロフィール情報を取得する（フォロワー数、プロフィール文、固定ポスト等）
4. 直近投稿をスクロールして7日分を収集する
5. 各投稿のエンゲージメント数を取得する

注意：
- ブロックされた場合は即座に方法Bに切り替える
- スクリーンショットを活用して画面の状態を確認する

#### 方法B: Web検索（フォールバック1）
1. WebSearchで site:x.com/{handle} や {handle} X(Twitter) で検索
2. 公開プロフィール情報を収集
3. 取れた範囲で進める

#### 方法C: 手動入力（フォールバック2）
A・Bで取れない情報はユーザーに聞く。不足分だけまとめて聞く。

### 4. 収集項目

各アカウントについて以下を収集する：

基本情報
- フォロワー数、フォロー数、総投稿数
- プロフィール文、固定ポスト、リンク先

投稿データ（直近7日分）
- 投稿内容、エンゲージメント数（いいね/RT/リプ/ブクマ）、投稿時刻
- 1日あたりの投稿数

投稿の分類
各投稿を以下のいずれかに分類する：
- 通常投稿（日常の価値提供・思想発信）
- ローンチポスト（商品・サービスの告知・販売）
- 導線ポスト（メルマガ/LINE/LP等への誘導）
- リプ・引用RT

構成・訴求の分析
- 通常投稿の構成パターン：フック→本文→締めの流れ
- ローンチポストの構成パターン：告知の入り方、オファーの出し方
- 訴求の仕方：何を訴求しているか（恐怖/損失回避/実績/変化/共感/選別）

### 5. 比較分析（11軸）

#### ① プロフィール設計
- プロフィール文の訴求力（何を伝えているか、実績、CTA）
- 固定ポストの役割（世界観浸透 or 導線接続）
- リンク先の設計（メルマガ / LINE / LP / リンクまとめ）

#### ② 投稿数・投稿頻度
- 総投稿数、日あたりの投稿数
- 投稿の継続性（毎日投稿しているか）
- 長文 vs 短文の比率、投稿ペースの安定感

#### ③ 投稿タイミング
- 投稿時間帯、ゴールデンタイムの活用

#### ④ コンテンツ戦略
- テーマの絞り方（1軸特化 vs 複数軸）
- 世界観浸透型 vs 導線接続型の比率
- 独自概念の有無と使い方
- 有益性 vs 思想性のバランス

#### ⑤ 通常投稿の構成
- フック→本文→締めの流れ
- 段落の切り方、話の展開パターン
- 1投稿あたりの情報密度
- 締め方のパターン（問いかけ / 断定 / 余韻 / CTA）

#### ⑥ ローンチポスト・販売投稿の構成
- ローンチ頻度
- 告知の入り方、オファーの出し方
- 緊急性・希少性の演出方法
- 社会的証明の使い方
- 販売期間中の投稿構成

#### ⑦ 訴求の仕方
- 主な訴求タイプ（恐怖・損失回避 / 実績・権威 / 変化・ビフォーアフター / 共感・代弁 / 選別・ふるい落とし）
- 訴求の組み合わせパターンと強度
- 感情の動かし方の順番
- 暗に売っている投稿の割合と手法

#### ⑧ フック力
- 冒頭の止め方のパターン
- 〝さらに表示〟を押させる設計
- タイトル・アイキャッチの強さ（記事の場合）

#### ⑨ エンゲージメント
- フォロワー数に対するエンゲージメント率
- どの投稿タイプが反応を取っているか
- いいね / RT / リプ / ブクマの比率
- 投稿数に対するエンゲージメント効率

#### ⑩ CTA・導線設計
- 誘導方法（メルマガ / LINE等）
- 誘導の頻度（毎回 vs 選択的）
- 誘導のトーン（直接的 vs 余韻型）
- プレゼント企画の有無

#### ⑪ トーン・世界観
- 文体の特徴
- ポジショニング（先生型 / 仲間型 / 観察者型）
- 差別化要素
- 一人称・二人称の使い方

### 6. 総合スコアリング

11軸をそれぞれ10点満点で採点し、合計110点満点のスコアを出す。
- 自分のスコアと競合平均スコアを並べて表示する
- 各軸のスコアも個別に表示する

### 7. 最大の強み / 最大の弱点

レポート冒頭に一言で宣言する。
- 例：「あなたの最大の強みは〝フック力〟、最大の弱点は〝CTA設計〟です」

### 8. 競合の高反応投稿の分析

競合ごとに直近7日間で「いいね数が上位3投稿」を抽出し、以下を分析する：
- 高反応投稿の共通点（フックの型、テーマ、構成、訴求、締め方、投稿時間帯）
- 自分の投稿パターンとの照合
- 自分がやっていない要素を「課題」として提示

> 特定の投稿を「なぜこの1行目か」「なぜこの改行か」という意図レベルまで深掘りしたい場合は `/x-intent-trace` を使うこと

### 9. 改善アクション

比較分析を元に、以下の3段階で改善点を出す。各アクションにインパクト（大/中/小）を付ける。

今すぐやること（今日中）
- プロフィール改善案を3案提示する（ヒアリングで得た背景情報を反映。参入経緯・実績数字・CTAを含む具体的な文面。Xのプロフィール文は改行が使えないため、改行なしで書くこと）
- ポスト案を3本出す（テーマ＋切り口＋なぜ今これを書くべきか）
- CTA文言テンプレを3パターン提示する（そのままコピペで使える）

今週やること（1週間以内）
- 投稿頻度調整、フックパターンの追加、CTA設計変更等
- 週間投稿スケジュールの提案
- 朝投稿テンプレ7本（1週間分の短文）

今月やること（1ヶ月以内）
- コンテンツ戦略の転換、独自概念の構築等

各改善点には：
- 何を変えるか
- なぜ変えるか（競合のどの要素から導いたか）
- 具体的なアクション（そのまま実行できるレベルまで落とす）
- インパクト（大/中/小）

### 10. 競合から盗むべき施策ベスト3

「この競合のこの施策を、あなたのトーンに合わせるとこうなる」まで具体化して3つ提示する。

### 11. 前回との差分比較（2回目以降）

同じディレクトリに前回のHTMLレポートファイルがある場合：
- 前回のスコアと今回のスコアを比較する
- 成長を可視化し、解消された課題・新しい課題を明示する
前回のレポートがない場合はスキップする。

### 12. レポート出力

分析結果をHTMLファイルで保存する。

- ファイル名：X競合分析_{日付}.html
- デザイン：黒背景、カード型レイアウト、色分けされた改善アクション
- 構成：
  1. 最大の強み / 最大の弱点（冒頭に一言）
  2. 総合スコア（自分 vs 競合平均）
  3. 前回との差分（2回目以降）
  4. 自分の数値サマリー（カード型）
  5. 競合サマリー（テーブル）
  6. 11軸比較分析（カード形式、各軸にスコア＋示唆/課題を色分け）
  7. 競合の高反応投稿の分析と課題
  8. 改善アクション（今すぐ / 今週 / 今月）＋インパクト表示
  9. 週間投稿スケジュール
  10. 競合から盗むべき施策ベスト3
- ブラウザで開くだけで閲覧可能（サーバー不要）

## 注意事項
- インプレッション数は他人のアカウントでは非公開。エンゲージメント数（いいね/RT/リプ/ブクマ）で代替する
- 数値が取れない項目は無理に推定せず、取れた範囲で分析する
- 改善点は具体的なアクションレベルまで落とす。抽象的な提案はしない
- 競合の施策をそのままコピーする提案はしない。ユーザーの世界観・トーンに合う形で取り入れる方向で提案する
- Playwrightが使えない環境でもWeb検索＋手動入力で動作する
