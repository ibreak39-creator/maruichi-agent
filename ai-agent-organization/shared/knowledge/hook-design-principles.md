# フック設計原則：1行目で全てが決まる

> **用途**: X投稿・note記事・メルマガ・セールスレターのあらゆる1行目（フック）を設計する際の絶対原則。
> コンテンツを作る前に必ずこのファイルを参照すること。

---

## フックとは何か

フックとは「スクロールを止める1行目」のことであり、コンテンツの命綱である。

どれだけ本文が良くても、1行目を読んでもらえなければ存在しない。
X（Twitter）においては、全ユーザーの90%以上が1行目だけを読んで「読む/読まない」を0.3秒で判断する。

> **フックは「コンテンツの質」ではなく「コンテンツに触れるかどうか」を決める。**

---

## フックの2大要素

強いフックには必ず以下の2つが含まれている。

### 要素①：ターゲットの明示

「これは自分への話だ」と即座に判断させる。

ターゲットを明示しないフックは、誰にも刺さらない広告と同じ。
逆にターゲットを明確に示すと、該当者は「自分のことだ」と感じて読み進める。

**明示の具体的方法**:
- 職業・状態で絞る：「情報発信者」「コンテンツ販売をしている人」「AI使ってるのに成果が出ない人」
- 行動で絞る：「ChatGPTを毎日使っている人」「Claude Codeを入れたばかりの人」
- 感情で絞る：「AIに振り回されてる感覚がある人」「手間が減らないと感じてる人」

**悪い例**:「AIエージェントについて話します」→ 誰が対象か不明
**良い例**:「コンテンツ販売をしているのにAIで手間が減らない人へ」→ 即座に当事者意識

---

### 要素②：強烈な問題点 or 理想の未来

ターゲットを引き止めた後、「読む理由」を1行で与える。

人は「痛みを避けたい」か「理想を手に入れたい」かのどちらかで動く。
フックはそのどちらかを**強烈に**提示しなければならない。

「強烈に」とは：
- 抽象的ではなく**具体的**（「効率化できる」ではなく「1日6時間が2時間になった」）
- ぼんやりではなく**断言**（「〜かもしれない」ではなく「〜だった」「〜になる」）
- 遠い未来ではなく**手が届く感覚**（「いつか変わる」ではなく「3週間で変わった」）

---

## フックの7パターン

### パターン①：数字で痛みを可視化
具体的な数字を使って「損失の大きさ」を見せる。

```
「毎回AIに一から説明する時間、月に換算すると〇時間消えてる計算になった」
「コンテンツ販売者がAI設計に費やす無駄な試行錯誤、平均3ヶ月分」
```

### パターン②：問題の正体を指摘する
「なんとなく感じてた違和感の正体」を言語化する。最も共感されやすい。

```
「情報発信者がAIを毎日使っても手間が減らない理由は、AIじゃなくて"設計"にあった」
「AIで書いた文章が自分らしくない理由、ようやく言語化できた」
```

### パターン③：反常識・逆説
読者が「当然だ」と思っていることを否定する。好奇心と読む動機を作る。

```
「ChatGPTを使いこなすより、使わなくて済む仕組みを作る方が早い」
「AIに多く教えれば教えるほど精度が落ちた。その理由」
```

### パターン④：Before/After の数字提示
変化を数字で示す。「自分もなれるか」という欲求と「どうやって？」という好奇心を同時に起こす。

```
「コンテンツ制作に1日6時間かけてた自分が、週2時間になるまでにやったことを書く」
「3週間前と今、1日の過ごし方が別人みたいになってた話」
```

### パターン⑤：比較による危機感
「今のままだと遅れる」という危機感を作る。

```
「AI単体で使い続ける情報発信者と、組織で動かす情報発信者。半年後に何が違うか考えた」
「テンプレから始めた人は即日稼働。ゼロから設計した自分は2ヶ月かかった」
```

### パターン⑥：理想の未来の具体描写
「そうなりたい」と強く思わせる。感情に直接訴える。

```
「X・note・メルマガをAI組織に任せて3週間。気づいたら企画だけしてた」
「フィードバックするたびにAIが自分の文体を覚えていく。この感覚を知ったらチャット型に戻れない」
```

### パターン⑦：告白・自己開示
失敗や本音の開示。信頼と共感を同時に作る。ローンチ後半で特に効く。

```
「AIエージェント組織をゼロから設計した結果、1ヶ月溶けた。やらかしたことを全部書く」
「正直に言う。明日のnote、こういう人には向いてない」
```

## 避けるべきフックの失敗パターン

### NG①：抽象的な「〜の話」
```
❌「Claude Codeについて話します」
❌「AIエージェント組織の話」
❌「今日は大事なことを書きます」
```
→ 何が得られるか不明。誰も止まらない。

### NG②：疑問文だけで終わる
```
❌「AIを使いこなせていますか？」
❌「あなたはAIを正しく使っていますか？」
```
→ 問いかけだけでは情報量ゼロ。止まる理由がない。

### NG③：メリットが抽象的
```
❌「AIで効率化できます」
❌「コンテンツ作りが楽になります」
```
→ 「どれだけ？」「どう楽に？」が伝わらない。

### NG④：主語が不明確
```
❌「毎回リセットされる問題を解決しました」
❌「組織化すると全然違う」
```
→ 誰が？何が？が抜けると読者は「自分のことか？」と判断できない。

### NG⑤：「タイトルっぽい」だけで内容がない
```
❌「AIエージェント組織化キットの紹介」
❌「情報発信者がAI組織を持つべき理由」
```
→ これは見出しであってフックではない。教育も感情も入っていない。

## フックと本文の関係

フックで引いた「約束」は本文で必ず回収する。

フックが「1日6時間が2時間になった」と言ったなら、本文でその方法を具体的に説明する義務がある。
フックだけ強くて本文が薄いと、信頼を失い次回から読まれなくなる。

> **フックは「本文を読む理由」。本文は「フックの約束の回収」。このセットで初めて機能する。**

---

## X投稿におけるフックの特殊ルール

- **1行目は140字以内に収まる独立した文として成立させる**（「もっと見る」を押さなくても意味が伝わる）
- **「、」や「。」ではなく改行で読ませる**（スマホ縦読みに最適化）
- **1行目の直後に空行を入れる**（視覚的な「間」が読む誘惑を作る）
- **フックは「問いかけ」より「断言」の方が強い**（自信があるように見える）

## ローンチ前投稿でのフック設計の原則

ローンチ前の教育投稿は、単に情報を届けるのではなく**「買いたい気持ちを育てる」**目的がある。
そのため、フックには以下の追加意識が必要：

1. **問題点フックは、読者がすでに感じている痛みを言語化する**（新しい問題を教えるのではなく、既存の痛みを「そういうことか」と腑に落とす）
2. **理想の未来フックは、読者がうっすら望んでいる状態を具体的に描く**（「そうなりたかった」と気づかせる）
3. **フックのテーマを一貫させる**（バラバラなフックは購買につながらない。「情報発信者×AI活用×次のステップ」という軸を保つ）
4. **シリーズで見た時に「物語」になっている**（単発で面白いだけでなく、続きを追わせる設計）
