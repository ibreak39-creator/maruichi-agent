# リード文パターン集

読者を引きつけるリード文の「型」をまとめたナレッジです。
毎回同じパターンにならないよう、記事のテーマに応じて型を使い分けてください。

**重要: リード文は最低15行以上書くこと。3-5文で終わるリード文は内容が薄すぎる。**

---

## リード文の設計思想（全型・全執筆の前提）

**型を使う前に、必ずこの設計思想を理解すること。型はこの思想を実現するための手段でしかない。**

リード文の目的はただ1つ。**「この記事を読まなければ損だ」と読者に確信させること。**

そのために、リード文の中で以下の**3段ロジックを完遂**させる。

### 3段ロジック

**① 理想の未来を強烈に描く**

「この記事を読み終えたとき、読者は具体的にどんな状態になれるのか」を言い切る。

- NG: 「〇〇について解説します」「分かりやすくお伝えします」← 何も見えない
- NG: 「〇〇ができるようになります」← 抽象すぎる。何が、どう変わるのか
- OK: 「今まで3時間かかっていた作業が、やり方を変えるだけで30分で終わるようになる。しかも出力の質は上がる」← 具体的に何が変わるかが見える

理想の未来は「どれだけ具体的に描けるか」が勝負。読者の頭の中にリアルなAfterの映像が浮かばないなら書き直す。

**② 問題点をぐりぐりと刺す**

「読者が今抱えている問題」を描写するだけで終わらない。

- 第1刺し: 「こういう問題があるよね」← 共感
- 第2刺し: 「なぜその問題が起きているのか」← 原因の掘り下げ
- 第3刺し: 「そのまま放置するとどうなるか」← 放置コストの提示

共感で終わらず、「やばい、自分のことだ。何とかしないと」まで感情を動かすのがゴール。1刺しで終わっているリード文は問題提起が甘い。

**③ この記事がその解消手段であることを示す**

①と②を踏まえた上で、「だから今回この記事を書いた」という接続を作る。

- NG: 「今回は〇〇について解説します」← 記事の内容説明になっている
- OK: 「この問題を解決した方法を今回全部まとめた。読めば△△の状態になれる」← 記事が「手段」として機能している

「記事が存在する理由」を読者に渡すこと。「読んでも読まなくてもいい情報」ではなく「読まないと損する情報」として提示する。

### 3段ロジックのチェック

リード文を書いたら、公開前に必ず以下を自問すること。

```
□ この記事を読み終えた後の読者の状態を、具体的に描写できているか
□ 問題の原因と放置コストまで踏み込んで刺せているか
□ 「だから読め」という接続が、記事への橋渡しとして機能しているか
```

3つ全部YESになっていないリード文は未完成。

---

## リード文の最終評価基準

どのパターン・構成のリード文を使っても、最終的に以下の3点を満たしているかを確認すること。

1. **理想の未来が具体的に見えるか**: リード文を読み終えた読者の頭の中に「この記事を読んだ後の自分」がリアルに浮かぶか。「〇〇について解説」止まりはNG
2. **問題点が3段まで刺さっているか**: 共感→原因の掘り下げ→放置コスト、の3段が揃っているか。「あるある」止まりはNG
3. **この記事が解消手段として機能しているか**: 「記事の内容紹介」ではなく「この問題を解決するための手段がここにある」という構造になっているか

記事のテーマや書き手の状態によってリード文の型・構成は変わる。特定の型に縛られず、「3段ロジックが完遂されているか」を最終判断軸として柔軟に組み立てること。

## リード文の基本原則

### 1文1文に「なぜそう言えるのか」を付ける
主張だけポンと書いて次に進むのは論理の飛躍。
「〇〇です」と書いたら、その直後に「なぜなら〜」「というのも〜」「実際に〜」と理由や根拠を必ず添える。

### 文と文の間には必ず「橋渡し」を入れる
前の文と次の文が唐突に切り替わらないよう、「でも」「そんな中で」「…と言っても」「まぁ」などの接続で思考の流れを見せる。

### 1つのステップに2-5文かける
「悩みを描写する」というステップでも、1文で終わらない。
具体的な場面→その時の感情→周りの状況→でも解決できなかった、のように膨らませる。

## 10個のリード文パターン（型）

### 型1: 読者の心の声 → 共感 → 原因の転換型

読者が心の中で思っていそうな不満やモヤモヤをセリフ形式で代弁するところから始める。「あ、自分のことだ」と思わせた後、共感を重ねてから「実は原因はそこじゃなくて」と視点を転換させる。

**展開の流れ:**
1. 読者の心の声をカギカッコで再現する（「〇〇じゃん…」）【②問題・第1刺し: 共感】
2. 「こんな風に思ったこと、ありませんか？」と問いかける
3. 「僕は何度もあります」と共感を示す
4. その悩みの具体的な場面をもう2-3文で深掘りする（どういう時に、どんな気持ちで、何を試したか）【②問題・第2刺し: 原因の掘り下げ → 「なぜそうなるのか」まで踏み込む】
5. 「でも、実は」と転換する【②問題・第3刺し: 放置コストを匂わせる。「このまま続けると〇〇になる」と1文入れる】
6. 本当の原因を引用ブロック等で提示する（ただし、ここでは概要だけ。詳しくは本文で）
7. **原因が分かったことで「具体的に何が変わるのか」を描く【①理想の未来: 「〇〇が△△になる」まで言い切る。「分かりやすくなります」はNG】**
8. 「それでは、いきましょう」等でスムーズに本文へ接続【③この記事が解消手段: 「だから今回まとめた」という接続を作る】

**例:**
```
「ChatGPT、全然良い答え返してくれないじゃん…」

こんな風に思った経験、ありませんか?僕は何度もあります。期待して使ってみたものの、「なんか微妙だな」と感じてしまう。プロンプトを工夫しても、指示を丁寧に書いても、なぜかピンとこない出力が返ってくる。

でも、実は、その原因って、プロンプトが下手だからじゃないんです。むしろ、

> **「前提条件が整ってない」**

ただそれだけなんです。

今回は、生成AIを使いこなす上で最も重要な、**「前提条件を整える」**という考え方についてお話しします。この考え方を理解するだけで、AIとのやり取りが驚くほど変わります。それでは、いきましょう。
```

### 型2: 哲学的問い → 自己紹介 → ぶっ飛んだ仮説型

普段あまり考えないような根本的な問いを投げかけて、読者の思考を揺さぶるところから始める。そこから自分の専門性を自然に紹介し、「こんなぶっ飛んだことを考えた」と告白する。

**展開の流れ:**
1. 大きな問いを投げかける（「〇〇と△△に違いはあるのだろうか」）
2. 「そんな風に考えたことはありますか？」と読者に振る
3. 自己紹介を挟む（肩書き + 日常の一場面）
4. 「そんな中、ある思考に辿り着きました」と発見をチラ見せ
5. その仮説を短く示す
6. 「ぶっ飛んだ発想」と自分でも認める（自己ツッコミ）
7. でもどうやって深めたかのプロセスを1-2文で説明する
8. 読み方の注意点やスタンスを示す
9. 本文へ接続

**例:**
```
生成AIと人に違いはあるのだろうか。あるいは同質なんだろうか。

そんな風に考えたことはありますでしょうか。

申し遅れました。しょーと申します。

現在、大学院でLLMの研究をしており、毎日のようにLLMについて思考し続ける生活を送っています。

そんな中、ある思考に辿り着きました。

人間も生成AIの仕組みからある程度は説明できるのでは

というぶっ飛んだ発想です。

でも浮かんだものは仕方がない。そう思ってClaudeと壁打ちしながら議論を深めて煮詰めたものを今回はnoteとして出すことにしました。

参考文献を載せられるわけではないですし、今回の話は事実に基づいたものではないです。そのことに注意しながら「1つの可能性」として楽しんでもらえると嬉しい限りです。

それでは、お話ししていきます。
```

### 型3: 権威 + ユーモア + 具体テーマ紹介型

自分の専門性を紹介しつつ、ユーモアや自己ツッコミを交えて親しみやすさを出す。「この人の話なら面白そう」と思わせた上で、今回の具体的なテーマを引用ブロック等で印象的に提示する。

**展開の流れ:**
1. 挨拶 + 自己紹介（肩書きを自然に）
2. 自分が何をやってきたか（専門性の根拠）
3. なぜ今回これを書くことにしたか（きっかけやエピソード）
4. ユーモアを入れる（自虐・読者いじり等で距離を縮める）
5. 読者の「めんどくさい」を代弁して共感する
6. 「だから僕が噛み砕いてお伝えします」と約束する
7. 今回のテーマが特別である理由を引用ブロック等で強調
8. テーマの概要を噛み砕いて1-2文で説明
9. 読者の感情を代弁（「面白そう！と思った方は〜」）
10. 本文へ接続

**例:**
```
こんにちは、しょーです。

普段、Xで発信してる僕ですが、本業は**「生成AIを研究する大学院生」**なんですよね。その本業のおかげもあってか、色々とおもろい論文も読んできてるわけです。

**「いっぱい知ってるのにもったいない…」**

と何回か発信者の方に説得されたので、重い腰を上げて、**「論文から見つめる生成AIの新たな使い方」**を紹介していくことにしました！

…と言っても、

となる方が9割だと思います。笑

僕も論文を読むのが嫌いです。院生なのに…

まぁ、「論文読むのがめっちゃおもろいんよねぇ」って1割の変態の方もいるかもですが、ほとんどの人は**論文をそのまま読むのはつらい**はずなので、今回はAIの力もお借りしながら、**「論文の内容から僕たちが試せる応用のやり方」**まで僕が解説しちゃいます。

今回のテーマは超おもろいので、何が何でも見てほしいと思ってます。なぜなら、

> **トヨタが研究している＆逆マトリックスのような夢のような研究**

だからです！

すご〜く噛み砕くと、**1,000名規模の仮想都市でそれぞれの人間をAIで再現してしまってシミュレーションしている**と言った研究になります。

**「なにそれ、面白そう！！！」**

と少しでも思った方は、絶対にこの記事を見ることをお勧めします。

それでは、少し難しいところもありますが、食らいついてきてください！
```

### 型4: ストーリー → 気づき → 「これ9割の人も同じ」型

実際にあったエピソードを具体的に描写して、読者を場面に引き込む。そこで起きた出来事を段階的に語り、最終的に「この問題、実はほとんどの人に当てはまる」と一般化して本文への動機を作る。

**展開の流れ:**
1. いつ・どこで・何をしていたかを具体的に描写【②問題・第1刺し: 読者が「自分の日常かも」と感じる場面設定】
2. その場面で起きた出来事を順を追って語る（セリフを入れる）【②問題・第2刺し: 「なぜその問題が起きたのか」の原因まで踏み込む】
3. 自分がどう思ったか、何を感じたかを正直に書く【②問題・第3刺し: 「このまま放置するとどうなるか」を1文入れる】
4. 原因を探った過程を1-2文で書く
5. 発見したことを示す（ここでも全貌は見せない。チラ見せ）【①理想の未来のチラ見せ: 「発見した後、具体的に何が変わったか」まで言う。「うまくいくようになった」はNG → 「〇〇が△△できるようになった」まで言い切る】
6. 「しかもこれ、〇〇な人全員に当てはまる」と一般化
7. **「同じ経験がある人は、ぜひ読んでみてほしい」等で本文へ接続【③この記事が解消手段: 「だから書いた / これを読めば同じ状態になれる」という構造にする】**

**例:**
```
先日、クライアントのプロンプトを添削してた時のこと。

「しょーさん、僕のプロンプト何がダメなんですか？もう3時間くらい格闘してるんですけど、全然思い通りにならなくて…」

って聞かれて、見てみたら指示自体はめちゃくちゃ丁寧なんですよ。文字数も十分、具体的な条件も書いてある。正直、パッと見は「これでいけるでしょ」と思ったくらいです。

でも出力結果はイマイチ。なんかぼやっとしてるというか、「惜しいけどそれじゃないんだよなぁ」って感じの回答しか返ってこない。

何が原因なのか1つずつ切り分けていくと、あることが完全に抜け落ちてたんです。指示は丁寧なのに、その「あること」がないだけで、AIは全然違う方向に走ってしまう。

しかもこれ、僕がこれまで添削してきた中で、9割くらいの人が同じポイントを見落としてました。「自分はちゃんと書いてるはずなのに…」と思ってる人ほど、ここが抜けてるんですよね。

今回はその見落としがちなポイントについて、実例を交えながらお話しします。心当たりがある方は、ぜひ最後まで読んでみてください。
```

### 型5: 数字のインパクト → 「嘘でしょ？」→ 実体験で証明型

具体的な数字を最初にドンと出してインパクトを与える。読者の「嘘でしょ？」という疑いに先回りして、自分の実体験や検証過程を具体的に語ることで信頼性を担保する。

**展開の流れ:**
1. 具体的な数字を含む主張をドンと出す【①理想の未来: 冒頭から「変化後の状態」を数字で突きつける。これが一番強い理想の未来の見せ方】
2. 読者の「嘘でしょ」を代弁する（「大げさに聞こえるかもしれませんが」）【②問題・第1刺し: 読者が今その数字を達成できていない問題を匂わせる】
3. 実際の検証過程や体験を2-3文で具体的に語る【②問題・第2刺し: 「なぜ以前はできなかったのか / 何が問題だったのか」まで掘り下げる】
4. なぜそうなったのか、仮説を1文で示す【②問題・第3刺し: 「この問題を知らないままだとどうなるか」を1文入れる】
5. この仮説を検証していく中で分かったことを本文で伝えると予告
6. **読者にとってのメリットを描く【①理想の未来の強化: メリットを「1文で示す」ではなく「読者が自分に置き換えて具体的にイメージできるレベル」まで描く。「役立ちます」はNG】【③この記事が解消手段: 「この記事でその方法を全部伝える」という接続を作る】**

**例:**
```
プロンプトの構造を変えただけで、出力の精度が体感で3倍になりました。

「いや、3倍って盛ってるでしょ」って思いますよね。正直、僕も最初は半信半疑だったんです。同じ内容を指示してるのに、書き方を変えるだけでそんなに差が出るわけないだろうと。

でも実際にやってみたら変わったんですよ。具体的に言うと、それまで3回くらいやり取りしてやっと使えるレベルだったのが、1回の指示でほぼ完成形が返ってくるようになった。作業時間で言えば、30分かかってたことが10分で終わるようになったわけです。

「なんでこんなに変わるんだ？」と気になって、AIの仕組みから逆算して考えてみたんです。すると、プロンプトの「構造」がAIの情報検索の精度を左右していることが見えてきた。

今回はその仕組みと、具体的にどう構造を変えればいいのかを、僕が実際に試した結果と一緒にお伝えします。同じことで悩んでる人には、かなり刺さる内容だと思います。
```

### 型6: 常識の提示 → 自分も信じてた → 研究で覆った型

多くの人が正しいと信じていることを提示し、「僕もそう思ってました」と共感してから、研究や実験を通じて「実は違った」と覆す。自分も同じ側にいたからこそ説得力が出る。

**展開の流れ:**
1. みんなが信じている常識を提示する
2. 「僕もそう思ってました」と同じ立場だったことを告白
3. いつ・何がきっかけで疑問を持ったかを描写
4. 調べた・検証した過程を1-2文で書く
5. 結果として分かったことを1文でチラ見せ
6. なぜ常識が広まったのか（誤解の理由）を推測
7. 正しい考え方を本文で伝えると予告

**例:**
```
「プロンプトは長く書けば書くほど良い結果が出る」

僕も2年前まではそう思ってました。とにかく条件を細かく書いて、制約を増やして、例も入れて…って、プロンプトをどんどん長くしていったんです。「情報量が多い方がAIも理解しやすいでしょ」と。

でもある時、研究室で面白い実験をしたんですよね。同じタスクに対して、500文字のプロンプトと100文字のプロンプトで出力を比較してみたんです。「長い方が絶対いいだろう」と思ってたのに、結果は100文字の方が精度が高かった。

「え、嘘でしょ？」って思って何度かやり直したんですけど、傾向は変わらなかった。

そこからAIがプロンプトをどう処理しているのか深掘りしていったら、大事なのは「量」じゃなくて「構造」だったということに気づいたんです。長く書いてもノイズが増えるだけで、AIが本当に必要としている情報がぼやけてしまう。

この話、実はプロンプトの書き方を教えてる界隈でもあまり語られてないんですよね。今回はこの「構造」について、できるだけ具体的にお話ししていきます。
```

### 型7: 対比（できる人 vs できない人）→ 差の正体を段階的に明かす型

同じツールを使っているのに結果が違う2人を対比させて、「なぜ差が出るのか」への興味を引く。その差の正体を一気に明かさず、少しずつヒントを出していくことで本文への期待を高める。

**展開の流れ:**
1. 同じツールを使っている2人の対照的な結果を描写【①理想の未来: 「できる人の結果」を具体的に描く。数字・場面・感情を入れて読者が羨ましいと思えるレベルまで】
2. 「この差って何なんだろう」と読者と一緒に考えるスタンスを取る【②問題・第1刺し: 「できない側」の問題を読者が自分事として感じる描写を追加する】
3. よくある説を否定する（「センスじゃないし、才能でもない」）【②問題・第2刺し: 「では本当の原因は何か」に向けて掘り下げる。読者が「じゃあ何が問題なんだ」と前のめりになるまで】
4. なぜそう言えるかの根拠を1-2文で示す【②問題・第3刺し: 「この原因を放置したまま使い続けると差は広がり続ける」と放置コストを入れる】
5. 差の正体のヒントを出す（全貌は本文で）
6. 読者が「自分はどっちだろう」と自問するような問いかけ
7. **本文への接続【③この記事が解消手段: 「できる人の状態になれる方法を今回全部まとめた」という接続にする。「解説します」はNG】**

**例:**
```
同じChatGPTを使っているのに、ある人は毎回「おお、これは使える！」と思える出力を引き出してる。一方で、ある人は毎回「うーん、なんか違うんだよな…」で終わって、結局手直しに時間をかけてる。

この差って、一体何なんでしょうか。

「AIリテラシーが高いからでしょ」「元々文章力がある人なんでしょ」って思うかもしれません。でも僕がこれまで100人以上のプロンプトを見てきた限り、センスとか才能とか、そういう話じゃないんですよ。

もっと言うと、プロンプトの「テクニック」の差ですらない。

じゃあ何が違うのか。実は、AIに向き合う時の「考え方」がたった1つ違うだけなんです。この考え方を持ってる人は、プロンプトが短くても長くてもいい結果を引き出せる。逆にこの考え方がないと、どんなテンプレを使っても「惜しい」止まりになってしまう。

あなたはどちらに当てはまりますか？

今回は、その「たった1つの考え方の違い」について、具体例をたっぷり交えながらお話しします。
```

### 型8: 告白 → 暗黒時代の描写 → 転機 → 今型

自分のダメだった時代を赤裸々に語り、読者との距離を一気に縮める。「この人も苦労してたんだ」という親近感から、「どうやって変わったんだろう」という興味につなげる。

**展開の流れ:**
1. 「正直に言います」「ぶっちゃけ」で本音モードに入る
2. 過去の失敗や恥ずかしい時期を具体的に描写（時期・状況・感情）【②問題・第1刺し: 読者が「自分も同じかも」と感じる問題の場面を共有】
3. その時に何を試して、何がダメだったかを1-2文で【②問題・第2刺し: 「なぜそれがダメだったのか / 何が根本原因だったのか」まで掘る】
4. 周りからどう見られていたか、自分がどう感じていたかを正直に書く【②問題・第3刺し: 「その状態が続くとどうなるか」の放置コストを入れる。過去の自分の末路として描写するのが自然】
5. 転機となった出来事やきっかけを描写
6. **そこから変わったことを描く【①理想の未来: 「変わった」という曖昧な描写はNG。「具体的に何ができるようになったか・何が変わったか」を言い切る。転機後の今の状態をリアルに見せる】**
7. 「あの頃の自分に教えてあげたい」等で共感を示す
8. **本文への接続【③この記事が解消手段: 「同じ状態にいる人がこの記事を読めば同じ変化が起きる」という接続を作る】**

**例:**
```
正直に言います。僕、生成AIを使い始めた頃は全然ダメでした。

大学院でAIの研究をしてるくせに、です。理論は分かる。仕組みも分かる。でもいざ実際に使ってみると、「なんか思ってたのと違う…」って毎回なってたんですよ。

「AIって結局こんなもんか」と思ってた時期すらあります。ChatGPTが話題になった時も、「使えるけど、言うほどすごくないよね」って冷めた目で見てました。

でもある日、研究室の後輩が僕の目の前でAIを使ってるのを見て、衝撃を受けたんです。同じChatGPTなのに、僕が使った時とは全然違うレベルの回答が出てきてる。

「え、なんで？何が違うの？」

って聞いたら、その後輩がやっていたのは、僕が完全に見落としていたシンプルなことでした。技術的に高度なことでもなんでもない。でもそれをやるかやらないかで、出力の質がここまで変わるのかと。

あの日から僕のAI活用はガラッと変わりました。今回は、あの頃の僕みたいに「AIって微妙だな」と思ってる人に向けて、僕が最初に知っておきたかったことを全部まとめます。
```

### 型9: トレンド → 「みんなが見てるポイントはそこじゃない」型

最新のニュースや話題を取り上げて、「みんなが注目してるところ」と「本当に重要なところ」のギャップを見せる。専門家の視点ならではの「別角度の解釈」を提示することで、読者に「この人の視点は違う」と思わせる。

**展開の流れ:**
1. 最新のニュースや話題を取り上げる
2. 世間の反応を描写する（SNSの声など）
3. 「僕は違うところが気になった」と視点をずらす
4. なぜそこが気になったのか、自分の立場から理由を説明
5. その視点から見ると何が見えてくるか、1文でチラ見せ
6. 読者にとってなぜ重要なのかを示す
7. 本文への接続

**例:**
```
先日、OpenAIが発表した新しいモデルが話題になりましたよね。

X(旧Twitter)を見ると、「すごい！」「もうこんなことまでできるの？」「やばすぎる」って声で溢れてました。確かに、デモを見た瞬間は僕も「おお」と思いました。

でも、大学院でAIを研究してる立場から正直に言うと、僕が一番ヤバいと思ったのはそこじゃないんです。

みんなが「すごい！」って言ってるのは表面的な性能の話で、本当にヤバいのはその裏にある「アーキテクチャの変化」の方なんですよ。これ、今はまだ地味に見えるかもしれませんが、半年後には僕たちの使い方を根本から変える可能性がある。

なぜそう言えるのか。それは、この変化が過去に起きた「ある転換点」と同じパターンを踏んでいるからです。

今回はその「本当にヤバいポイント」について、研究者の視点からできるだけ分かりやすくお話しします。AIを日常的に使ってる人にとっては、かなり重要な話になると思います。
```

### 型10: 問いかけ → 深掘り → 「答えが見つかった」型

読者に問いかけて一緒に考えるスタンスを取りつつ、その問いに対して自分なりの答えを見つけたことを伝える。「教えてあげる」ではなく「一緒に考えよう」のトーンが特徴。

**展開の流れ:**
1. 素朴な問いかけから始める
2. 「考えたことありますか？」と読者に振る
3. 自分がこの問いと向き合ったきっかけを描写
4. 最初は分からなかったこと、悩んだことを正直に書く
5. 試行錯誤の過程を1-2文で
6. 「ある答え」に辿り着いたことを示す
7. でもその答えは一般的ではないことを認める
8. 「1つの考え方として」読んでほしいとスタンスを示す
9. 本文への接続

**例:**
```
生成AIを使っていて、「なんかこれ、自分じゃなくても書けるよな」と思ったこと、ありませんか？

僕は何度もありました。時間かけてプロンプトを書いて、出てきた文章を読んで、「…うん、まぁ、間違ってはないけど」みたいな。正しいんだけど、どこかつまらない。誰が書いても同じになりそうな、無難な文章。

最初は「AIの限界なのかな」と思ってたんです。所詮はパターンの組み合わせだから、個性のある文章は無理なんだろうなと。

でもある時、ふと気づいたんですよね。AIに個性がないんじゃなくて、僕がAIに「自分の個性」を渡してなかっただけだったんです。

「いや、それどういうこと？」ってなりますよね。僕も最初はそう思いました。でもこの考え方を理解してからは、AIと一緒に「自分にしか書けない文章」を作れるようになったんです。

今回はその考え方について、できるだけ具体的にお話しします。「AIの文章って無難だよなぁ」と感じてる人には、きっと新しい発見があると思います。
```

## リード文テンプレート（5個）

以下は、テーマに応じて穴埋めで使えるテンプレートです。
**注意: 各ステップに2-3文は書くこと。1ステップ1文は肉づけ不足。**

### テンプレートA: 読者の心の声 → 共感 → 原因転換

```
「{読者が心の中で思っている不満・モヤモヤをセリフ形式で}」

こんな風に思った経験、ありませんか？僕は何度もあります。{その悩みを感じる具体的な場面を2文で描写}。{何を試したけどダメだったかを1文で}。

でも、実は、その原因って、{みんなが思っている原因}じゃないんです。むしろ、

> **「{本当の原因}」**

{本当の原因をもう少し噛み砕いて説明する1文}。

今回は、{テーマの概要}についてお話しします。{この考え方を知ることで得られるベネフィットを具体的に1文}。それでは、いきましょう。
```

### テンプレートB: 権威 + ユーモア + テーマ紹介

```
こんにちは、しょーです。

{自分が何をしている人間かを1-2文で紹介}。{その活動の中で得た経験・知識について1文}。

{今回の記事を書くことにしたきっかけ（人に言われた、自分で気づいた、ある出来事があった）を2-3文で}。

…と言っても、{読者が感じそうな心理的ハードル（めんどくさい、難しそう等）を代弁する1文}。

{自己ツッコミやユーモアで距離を縮める1-2文}。

{「だから僕が噛み砕いてお伝えする」という約束を1文}。

今回のテーマは{テーマへの熱量を込めた表現}。なぜなら、

> **{テーマが特別である理由を端的に}**

{テーマを噛み砕いて読者が分かるレベルで1-2文で説明}。

{読者の感情を代弁する1文（「面白そう！と思った方は〜」等）}。

それでは、{本文への接続}。
```

### テンプレートC: ストーリー → 発見 → 一般化

```
{いつ・どこで・何をしていたかの場面描写1文}。

{その場面で起きた具体的な出来事を、セリフを交えて3-4文で順を追って描写}。

{自分がその時どう思ったか・何を感じたかを正直に1-2文}。

{原因を探った・調べた過程を1-2文}。すると、{発見したことの概要を1文}。{ただし全貌はまだ見せず、チラ見せに留める}。

しかもこれ、{この発見が多くの人に当てはまる理由を1-2文}。

今回は{テーマの概要}について、{どのように伝えるか（実例を交えて等）}。{ターゲット読者への呼びかけ1文}。
```

### テンプレートD: 対比 → 差の正体 → 読者への問いかけ

```
同じ{ツール・手法}を使っているのに、{うまくいく人の具体的な結果の描写}。一方で、{うまくいかない人の具体的な結果の描写}。

この差って、一体何なんでしょうか。

{よくある説を1つ挙げて否定する。なぜ否定できるかの根拠も1文で}。もっと言うと、{さらに別の説も否定。「〜の差ですらない」}。

じゃあ何が違うのか。実は、{差の正体を1文で示す}。{その考え方を持つ人と持たない人で何が変わるかを1-2文で対比}。

あなたはどちらに当てはまりますか？

今回は、{テーマの概要}について、{どのように伝えるか}。
```

### テンプレートE: 告白 → 暗黒時代 → 転機 → 共有

```
正直に言います。僕、{過去の失敗・恥ずかしい体験を1文}。

{その時の状況をもう少し詳しく2-3文。何をやっていて、どうダメだったか}。

{その時の心境・周りの反応を1-2文}。

でも{転機のきっかけとなった出来事を2-3文で具体的に描写}。

{転機で分かったことの概要を1文}。{それは技術的に高度なことではないと添える1文}。

{変化後の今を1文}。今回は、{過去の自分のような読者への共感を込めた呼びかけ1文}、{テーマの概要}を全部まとめます。
```

## 使い分けガイド

**重要: 型はあくまで「どの順番で3段ロジックを展開するか」の違いでしかない。どの型を選んでも、最終的に「①理想の未来を強烈に描く」「②問題点を3段まで刺す」「③この記事が解消手段であることを示す」の3段ロジックが完遂されていること。型を選んだ時点で安心しない。**

| 記事のタイプ | おすすめの型 |
|-------------|-------------|
| ノウハウ系 | 型1(心の声), 型5(数字), 型7(対比) |
| 論文紹介系 | 型6(常識破壊), 型9(トレンド), 型3(権威+ユーモア) |
| 体験談系 | 型4(ストーリー), 型8(告白), 型10(問いかけ) |
| 商材導線系 | 型1(心の声), 型10(問いかけ), 型7(対比) |
| トレンド解説系 | 型9(トレンド), 型6(常識破壊), 型5(数字) |
| 思考実験系 | 型2(哲学的問い), 型10(問いかけ), 型6(常識破壊) |

## パンチライン配置ルール（重要）

リード文にはパンチライン（読者の心にグサッと刺さる一撃フレーズ）を**スパイスとして1〜2箇所**配置すること。

### パンチラインとは
- 短くて切れ味のある言い切りフレーズ
- 読者が「おっ」と思わず手を止める一文
- 記事全体のメッセージを凝縮した言葉

### パンチラインの配置位置
- **リード文の冒頭1〜2文目**: 最初の一撃で読者を掴む
- **引用ブロックの中**: 記事の核心メッセージとして印象に残す
- **リード文の締め直前**: 本文に入る直前のブースター

### パンチラインの良い例
```
AIをフル活用してる人ほど、ある落とし穴にハマっている。
```
```
ぶっちゃけ、それって自分がやる必要ありますか。
```
```
自分のフィルターを通さないインプットは、ただのコピペだ。
```

### パンチラインのNG例
```
この記事ではインプットの重要性について解説します。（← 説明文。パンチがない）
```
```
インプットは非常に重要な要素です。（← 抽象語。刺さらない）
```

### パンチラインのコツ
- **短く言い切る**（20字以内が理想）
- **読者の常識を覆す**か、**痛いところを突く**
- **動詞で終わる**か、**体言止め**で切れ味を出す
- スパイスなので多用しない（リード文中1〜2箇所で十分）

## 注意事項

- **毎回違う型を選ぶ**: 直近3記事と同じ型は避ける
- **型の組み合わせもOK**: 例えば「問いかけ + ストーリー」のようにミックスしてもよい
- **テンプレートの丸写し禁止**: テンプレートは構造の参考であり、言い回しは毎回変える
- **最初の1文が勝負**: リード文の最初の1文で読者を止められなければ負け。パンチラインを冒頭に配置せよ
- **最低15行以上**: リード文が短すぎると内容が薄くなる。しっかり肉づけする
- **論理を飛躍させない**: 主張の後には必ず「なぜそう言えるか」を添える。文と文の間に必ず橋渡しを入れる
- **パンチラインを忘れない**: リード文中に1〜2箇所、読者の心に刺さる一撃フレーズをスパイスとして配置する
